# Order Desk

Учебное приложение для создания и редактирования заказов. Страница `/orders` показывает заказы от новых к старым и даёт ссылки на три варианта формы. Данные хранятся в PostgreSQL.

Стек: Next.js (App Router), TypeScript в строгом режиме, PostgreSQL 17, Docker Compose, Prisma 7 и Zod 4.

## Запуск

Нужны Node.js 22.12+ из ветки 22 или Node.js 24+, npm и запущенный Docker с Compose v2.

```bash
npm ci
cp .env.example .env
docker compose up -d --wait
npm run db:migrate
npm run db:generate
npm run dev
```

Откройте [http://localhost:3000/orders](http://localhost:3000/orders). Если `.env` уже есть, используйте его: `DATABASE_URL` должен соответствовать `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`. Эти параметры задаются при первом создании тома. Compose хранит данные в именованном томе `postgres_data`; обычный перезапуск приложения или контейнера их сохраняет.

`npm run db:migrate` применяет миграции из `prisma/migrations` к базе. `npm run db:generate` создаёт файлы Prisma Client для приложения. При изменении модели в локальной разработке выполните `npx prisma migrate dev --name имя_изменения`, затем снова сгенерируйте клиент.

## Как работают формы

| Страница | Отправка данных |
| --- | --- |
| `/orders/v1` | JSON через `fetch` и Route Handler |
| `/orders/v2` | `FormData` через `form action` и `useActionState` |
| `/orders/v3` | Значения из React state через вызов Server Action |

Во всех вариантах есть создание и редактирование. Общие поля показывают ошибку сразу при изменении. Браузер блокирует отправку, пока поле не исправлено. Одна схема Zod проверяет типы в браузере и на сервере. Правила длины комментария и размера файла проверяются обычными `if`.

Непустой комментарий после `trim` должен содержать минимум 3 символа и занимать не больше 250 байт в UTF-8. Пустой комментарий или `null` очищает поле. Если при редактировании поле `comment` пропущено, старый комментарий сохраняется.

Картинки PNG и JPEG до 2 МБ загружаются через `v2`. Сервер проверяет содержимое файла и создаёт имя. Сами файлы находятся в локальной папке `uploads/`, а PostgreSQL хранит их имена. При выборе нового файла старый удаляется после записи в базу. Файл без замены сохраняется во всех трёх вариантах.

Страницы получают заказы через `lib/orders.ts`, преобразуют их в DTO и передают списку. Формы и API используют тот же сервис для сохранения.

| Запрос | Что делает |
| --- | --- |
| `GET /api/orders` | Возвращает список от новых заказов к старым. |
| `POST /api/orders` | Создаёт заказ и возвращает `201`. Пустой объект создаёт заказ со статусом `NEW`. |
| `PATCH /api/orders/1` | Сохраняет статус и комментарий заказа №1 и возвращает `200`. |
| `GET /api/orders/1/image` | Отдаёт изображение заказа №1, если файл есть. |

`POST` и `PATCH` возвращают `{ success: true, data }` или `{ success: false, error }`. Ответы с ошибками валидации содержат сообщения для конкретных полей.

## Проверка

- Создайте два заказа: второй должен оказаться сверху.
- Измените статус одного заказа, например с `NEW` на `PAID`.
- Остановите Next.js, снова запустите `npm run dev` и откройте `/orders`. Заказ и новый статус должны остаться.
- Через инструменты разработчика поменяйте значение выбранного `option` на `INVALID` и отправьте форму. Должно появиться сообщение об ошибке; заказ не создастся или его статус останется прежним.
- `npm run lint` и `npm run build` проверяют код и сборку.
