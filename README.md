# Order Desk

Учебное приложение для создания заказов и изменения их статусов. Страница `/orders` показывает номер, время создания и статус. Новые заказы идут первыми, данные хранятся в PostgreSQL.

Стек: Next.js (App Router), TypeScript в строгом режиме, PostgreSQL 17, Docker Compose, Prisma 7 и Zod 4.

## Запуск

Нужны Node.js 22.12+ из ветки 22 или Node.js 24+, npm и запущенный Docker с Compose v2.

```bash
npm ci
cp .env.example .env
docker compose up -d --wait
npm run db:migrate
npm run db:generate
npm run dev
```

Откройте [http://localhost:3000/orders](http://localhost:3000/orders). Если `.env` уже есть, используйте его: `DATABASE_URL` должен соответствовать `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`. Эти параметры задаются при первом создании тома. Compose хранит данные в именованном томе `postgres_data`; обычный перезапуск приложения или контейнера их сохраняет.

`npm run db:migrate` применяет миграции из `prisma/migrations` к базе. `npm run db:generate` создаёт файлы Prisma Client для приложения. При изменении модели в локальной разработке выполните `npx prisma migrate dev --name имя_изменения`, затем снова сгенерируйте клиент.

## Как работают формы

1. Форма отправляет JSON с выбранным статусом через `fetch`. Для нового заказа по умолчанию выбран `NEW`.
2. `z.enum(OrderStatus)` проверяет, что статус есть в списке. `optional()` позволяет при создании пропустить поле, и тогда база подставляет `NEW`. При смене статуса поле обязательно. `safeParse` возвращает проверенные данные в `result.data` при успехе. При ошибке API возвращает `400`, а форма показывает сообщение.
3. После успешной записи через Prisma форма вызывает `router.refresh()`. Сервер перечитывает список, и изменения появляются на странице. Пока запрос выполняется, кнопка формы заблокирована.

Страница `/orders` читает список напрямую через Prisma. API использует тот же запрос для списка и обрабатывает запись в `app/api/orders`.

| Запрос | Что делает |
| --- | --- |
| `GET /api/orders` | Возвращает список от новых заказов к старым. |
| `POST /api/orders` | Создаёт заказ из JSON, например `{"status":"NEW"}`. Пустой объект создаёт заказ со статусом `NEW`. |
| `PATCH /api/orders/1` | Меняет статус заказа №1. Пример тела запроса: `{"status":"PAID"}`. |

## Проверка

- Создайте два заказа: второй должен оказаться сверху.
- Измените статус одного заказа, например с `NEW` на `PAID`.
- Остановите Next.js, снова запустите `npm run dev` и откройте `/orders`. Заказ и новый статус должны остаться.
- Через инструменты разработчика поменяйте значение выбранного `option` на `INVALID` и отправьте форму. Должно появиться сообщение об ошибке; заказ не создастся или его статус останется прежним.
- `npm run lint` и `npm run build` проверяют код и сборку.
